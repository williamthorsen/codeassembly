# Agent guidance content

This directory contains the source-of-truth guidance content that `codeassembly install` renders into platform-specific files (`~/.claude/CLAUDE.md`, `~/.rovo/AGENTS.md`).

This README is for maintainers of this directory. It is not referenced by any `<!-- include: -->` directive and is not part of the rendered output.

## `shared/AGENTS.md`

Inlined into every rendered platform guidance file via the directive expander, which puts it in every session that loads one of those files. It has no destination of its own; `install` deployed a copy to `~/.agents/AGENTS.md` until that tier was retired, and both `install` and `uninstall` now remove what it left there.

A subagent loads no platform guidance file, so a section its role's work needs is inlined from `_partials/` instead. This file composes from those same partials rather than restating them, which is what keeps the two routes from drifting: A section that reaches some subagent lives in a partial both hosts include, and one that reaches none stays written out here. `content/test-utils/shared-doctrine-carriers.ts` holds the per-role coverage, and `content/__tests__/shared-doctrine-reach.unit.test.ts` asserts it along with the order the sections render in.

## Ambient delivery: Harness regions

A rulebook with `delivery: ambient` is delivered by `sync` into the ambient region (`<!-- codeassembly-ambient:start -->` / `<!-- codeassembly-ambient:end -->`) of a per-harness guidance file, wrapped in `<!-- rulebook:<slug> -->` sentinels, with `<!-- rulebook-version: <version> -->` directly below the open sentinel where the rulebook declares a version. The region opens with a comment naming its content generated and warning that edits inside the region are overwritten; the comment is part of the rendered body, so a region with no ambient content has none. Both domains work this way, and both are mechanical end to end: Every host is a file its harness loads at launch, with no agent-elective read anywhere on the path. They differ in which file, and in who creates the region.

- **Home / all-projects scope** (`sync --global`): The host is each targeted harness's guidance file under its home directory (`~/.claude/CLAUDE.md`, and the equivalent under each other harness's home). The templates in `_harnesses/` contain the empty region, so the region's location is `install`'s decision while its content is `sync`'s: `sync --global` regenerates the region wholesale each run, and `install` splices the region's content into every re-render and excludes it from drift hashing (`ambient-region.ts`). Hand edits outside the region still count as drift. Run `install` before the first `sync --global`; a guidance file that is missing or has no region is skipped with a warning naming the fix.
- **Project scope** (`sync`): The host is each targeted harness's machine-local project guidance file at the project root (`CLAUDE.local.md`, `AGENTS.local.md`). `install` does not manage user-local files, so `sync` owns region creation here: An absent host is created with the region, and a host that already exists keeps everything it contains and gains the region below it. A host is materialized only when the scope declares an ambient rulebook, so a project that declares none is left with no file; and a host with a half-written region fails the run rather than being appended to, since appending beside a stray marker would delete the text between them on the following sync. Because the host is gitignored, it exists only in the worktree that created it, so a multi-worktree checkout needs a sync per worktree; `sync` warns when a host it writes is not git-ignored.

**Destination tiers.** Harness-neutral and per-harness destinations are not interchangeable. A project's root `AGENTS.md` is the one neutral destination: One body of text serves every harness, so it cannot contain a harness-scoped path, and content that needs one belongs in an ambient rulebook instead. Every generated destination has a known target harness: skills, subagents, and both ambient tiers. The root `AGENTS.md` receives no generated content at all. It is hand-authored, and `sync` strips the rulebook blocks a previous version left there or in the `.agents/PROJECT.md` it superseded.

Two files under `~/.agents/` are retired. `GLOBAL.md` was the home ambient host: `sync --global` strips the sync-owned blocks from a legacy copy and deletes the file once nothing hand-written remains. `AGENTS.md` was a verbatim copy of `shared/AGENTS.md`: `install` and `uninstall` each remove a copy the CLI deployed, keep one carrying hand-written content, and leave a copy it never deployed alone. For machine-local guidance that should stay out of source control, declare a machine-local source in `~/.agents/codeassembly.yaml` (a directory shaped like the library's `content/`, with rulebooks at `guidance/rulebooks/<slug>.md`) and give the rulebook `delivery: ambient`; it then uses the same injection as library rulebooks.
